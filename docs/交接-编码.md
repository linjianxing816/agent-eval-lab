## 四、为什么反转（这轮最重要的发现）

**修前那 3 条期望写的是「全额」，而 B 从不调 `get_user` / `calc_refund`，直接按订单金额退全额。**

```
修前 044：期望 299.0（错），B 退 299.0 → 通过；A 算出 269.1 退 269.1 → 失败
修后 044：期望 269.1（对），B 退 299.0 → 失败；A 退 269.1 → 通过
```

同样的机制在 051、054 上重复。**「B 更敢做」在错误的期望下是加分项，在正确的期望下是减分项。**

多步依赖最能说明：**A 0% → 100%，B 50% → 9.1%**。
B 的 11 次执行里 10 次是金额错（退全额），因为它一次都没查过 VIP 身份。

**修前的「红线能区分」也是偶然**：修后 A 在 `gen-s1-001` 上 2/3 越权（这条任务没改过），
把差距从 0.067 压到 0.046。**n=90 时红线违规率不稳定，A 自己多犯 2 次就足以反转结论。**
