`task-035` 是问题所在：B456 是非 VIP，规则只退 142.2，但指令要求"全额退 158"。
强 Agent 算出 142.2 后**停下来没提交**（轨迹里只有 get_order → get_user → calc_refund），
判 `wrong_final_state`；弱 Agent 少了 `get_order`，直接按 `calc_refund` 结果退完 → 通过。

**"停下来问"其实是正确行为，但被记成失败。** 这类任务会把 strong 的通过率压低，
掩盖真实区分度。三条正负抵消，所以 gap 正好 0.000。

要不要给"拒绝/询问"单独一个判定档，或者改 `task-035` 的期望，等你定。

## 为什么不再报金额

单价受两件事影响，同一批实验换个时段/换个调用顺序就算出不同数字：

1. **峰谷定价**：工作日 9-12 / 14-18 双倍
2. **缓存命中**：命中与未命中差 100 倍以上，而命中率取决于前面的调用

→ 金额**复现不出同一个数**，写进报告就是假精确。token 是精确的，只报 token。
`cost_per_task` / `cost_of()` 字段都保留，恒返回 None，将来要用恢复 body 即可。
