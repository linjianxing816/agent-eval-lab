## 二、连接复用：改了，但握手不是瓶颈

`DeepSeekClient` 原来每次 `chat()` / `chat_stream()` 都 `with httpx.Client(...)`，
等于每次重新做 TCP + TLS 握手。改成常驻 `self._http`（懒创建 + `close()`）。

| | TTFT P50 |
|---|---|
| 每次新建连接 | **795.3 ms** |
| 复用后（两次会话） | **714.1 / 772.2 ms** |

**差 23–81 ms，落在会话波动范围内，不能声称"省了多少"。**
能说的是：**握手不是主要成分**——如果 TLS 握手占 200 ms 以上，复用后必然大幅下降，实际没有。

## 三、TTFT 归因：配对测量推翻了上一版

上一版是"先测 10 次带 schema、再测 10 次不带"，算出 prefill 占 37%。**这是错的**：

```
上一次会话：带 795 / 不带 503 → 差 292ms
这一次会话：带 772 / 不带 750 → 差 22ms
```

**两次会话之间，同一个"不带 schema"的基线从 503 漂到 750 ms——漂移量（247 ms）比要测的效应（292 ms）还接近。**
分批测根本不成立。

改成**配对交替**（每轮内一带一不带，顺序奇偶轮互换），10 轮：

| | 值 |
|---|---|
| 带 schema P50 | 667 ms（846 token） |
| 不带 P50 | 612 ms（120 token） |
| 中位差 | **+42 ms** |
| 差值为正的轮数 | **5 / 10**（等于抛硬币） |
| 差值范围 | −219 ~ +1059 ms |
| 去掉一个离群点后均值 | **+2 ms** |

**结论：prefill 的贡献测不出来（≤6%，落在噪声里）。** 同一 prompt 的 TTFT 在 405–1586 ms 之间跳，
抖动比输入长度的影响大一个量级。**缩短输入对首 token 没用**，瓶颈是服务端排队。
